## Decisions

**The srcset is built from rows that exist, never from the key pattern.**
`MediaAsset.key` is `@unique`, so each derivative is its own row, and #42's media
route authorises a request _by looking that row up_. A srcset generated by
pattern-substituting widths into a key therefore 404s for every derivative that
has not been registered. Measured on this branch: the registered key returned
302, a guessed sibling returned 404. `getPublishedProject` collects the sibling
rows by shared key stem in a single `OR … startsWith` query. This degrades
correctly in both directions — one registered derivative renders one source, and
once #28 registers all eight the full set appears with no change here.

**LQIP is a stacked `<img>`, not a CSS background.** Two constraints force it:
CSP blocks static `style=""` attributes (#11), and CSS cannot read a `data-`
attribute into a `url()` — `attr()` does not work there. A stacked image also
needs no script to dismiss: the real image occupies the same box and paints over
it once decoded. `img-src 'self' data:` is what permits the data URI.

**`sizes` is measured, not guessed.** It was first written as
`(min-width: 1024px) 66ch, 100vw`. That is wrong: in `sizes`, `ch` resolves
against the _root_ font, not the content font, and it under-declared the box
badly enough that a 1230px-wide image downloaded the 960w file. The figure spans
the content container, which measures 286/341/638/894/1230 px at
320/375/768/1024/1440. The container caps at 1230px, so above 1440px a fixed
`1240px` stops the 1920w file being fetched for a box that can never use it — a
2x screen still scales up to it correctly.

## Verified

Gate: `typecheck` 0 errors / 0 warnings / 0 hints · `lint` PASS · `test` 118
passed (7 files) · `build` PASS.

Against a real MinIO bucket and real `MediaAsset` + `ProjectImage` rows, three
distinct images on one project page:

| Acceptance criterion                      | Result                                                                                                                         |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| CLS < 0.05 with three images              | **0.0000** at 375px/2x, network throttled to 400 kbps so images arrive after first paint                                       |
| Format negotiation                        | Chrome (AVIF-capable) chose `*.avif` at every width; every fallback `<img src>` is `*.webp`, never AVIF — see limitation below |
| No image without `alt`, `width`, `height` | all 6 image elements on the page carry all three                                                                               |
| No storage hostname in page source        | 0 hits for `minio`, `9000`, `amazonaws`, `s3.`, `X-Amz`                                                                        |

Candidate selection, measured box width vs. file actually downloaded:

| Viewport | Box  | Downloaded      |
| -------- | ---- | --------------- |
| 320      | 286  | `img-480.avif`  |
| 375      | 341  | `img-480.avif`  |
| 768      | 638  | `img-960.avif`  |
| 1024     | 894  | `img-960.avif`  |
| 1440     | 1230 | `img-1440.avif` |
| 1920     | 1230 | `img-1440.avif` |

No horizontal overflow at any of those widths. All eight derivative URLs return 302. Loading: first image `eager`/`fetchpriority=high`, the rest `lazy`.

**Limitation, stated plainly:** the "browser that does not support AVIF" half of
the negotiation criterion was _not_ exercised in a real legacy engine — none is
installed here. It is verified structurally instead: the AVIF `<source>` is
first, a WebP `<source>` follows, and the `<img>` fallback is always WebP, so an
engine without AVIF skips to WebP by `<picture>` semantics. Worth a real check in
#39's Playwright sweep.
